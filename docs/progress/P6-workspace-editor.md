# 工作区文本编辑与保存

## 构建诊断定位

主界面构建状态保留结构化诊断；日志对话框列出可点击的源码位置。
点击后使用 DiagnosticLocation 验证文件仍位于当前工作区且存在，再打开并定位文本行。
编辑器使用 TextFieldValue 选择目标行，旧行号超过文件末尾时定位到末尾。
工程外/生成目录、无有效行号或已删除文件拒绝跳转；已有未保存草稿时不切走覆盖。
启动构建也会提示先处理未保存编辑，避免误以为磁盘构建包含草稿。

3 个路径/行号测试通过，主 APK 构建通过。诊断点击、键盘和自动滚动的可见 UI
验收仍待解锁设备后进行；单元测试不替代该项。

## 草稿恢复更新

编辑内容现在异步写入 app-private editor-drafts，按项目/路径摘要隔离，不进入源码快照或 Git。
记录原始磁盘摘要与草稿正文；递增版本拒绝迟到写入，防止旧任务覆盖新草稿或复活已丢弃草稿。
打开文件时等待最新落盘任务并恢复草稿；磁盘已变化时保留旧摘要并提示冲突，保存仍会拒绝覆盖。
若草稿已与磁盘相同则忽略，处理“源码已保存、草稿清理前进程退出”的情况。
成功保存及用户确认丢弃后删除对应草稿。

3 个草稿单元测试通过。真机两阶段测试先持久化草稿，结束仪器进程并 adb force-stop，
再启动新的仪器进程恢复；中文草稿与未修改源码均正确，随后模拟外部修改，覆盖被拒绝。
证据：p6-evidence/draft-prepare-test.txt、draft-recovery-test.txt 与 EditorDraftStoreTest XML。

此证据覆盖持久化层跨进程恢复；编辑 UI 的视觉/输入法与强杀瞬间尚未完成的异步写入仍需验证。
未完成的最后一次异步落盘不能保证恢复，界面在持久化失败时显示错误。

2026-09-27：主界面文件入口已接 WorkspaceEditorScreen，替代原先可能截断的只读预览入口。
只对完整 UTF-8 文档开放编辑，512 KB 上限、二进制 NUL 与无效编码明确拒绝；错误信息不是可保存内容。

WorkspaceTextFile 保存前比较打开时的 SHA-256，写入临时文件后再次检查，再原子替换。
保留 UTF-8 BOM、原有换行文本以及 POSIX mode（包括可执行位）。外部内容变化时拒绝保存，
用户草稿留在界面；不自动覆盖较新的 Agent 修改。该机制是乐观并发检查，不声称对不协作
的外部写入者提供跨进程 compare-and-swap 原子保证。

UI 提供 Save、未保存标记、保存结果、未保存退出确认；Agent/构建/终端运行时暂停编辑与保存。
异步打开使用请求编号和项目 ID 防止旧结果写入新页面，保存期间禁止关闭。

已验证：主 APK 与测试 APK 构建通过；5 个核心编辑存储测试通过。
真机存储测试通过：中文/BOM/CRLF 完整保存、可执行权限保留、外部修改冲突拒绝与临时文件清理。
证据见 [p6-evidence](p6-evidence/editor-storage-test.txt)。

尚未验证可见界面与输入法交互。进程死亡后的草稿恢复、诊断跳转、语法高亮/语言服务、
